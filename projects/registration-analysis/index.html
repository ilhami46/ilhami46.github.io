Registration & Data Quality Analysis

An analysis framework for identifying repeated registrations, validating account-level behaviour, and separating duplicate-account patterns from successful verification outcomes.

SQLPythonData QualityValidation

Business problem

Multiple registrations can distort user counts and funnel metrics. The analysis needs to identify repeated registrations while preserving a clear distinction between unique users, accounts, and verified accounts.

31,452unique users in the analysed example
2,290users with more than one account
1verification example shown without personal data

Visual summary

Analysis workflow

01Standardise emails
02Group registrations
03Flag repeats
04Check verification
05Report patterns

Example SQL

SELECT
    LOWER(TRIM(email)) AS email_key,
    COUNT(*) AS account_count,
    SUM(CASE WHEN email_verified = 1 THEN 1 ELSE 0 END)
        AS verified_accounts
FROM registrations
GROUP BY LOWER(TRIM(email))
HAVING COUNT(*) > 1
ORDER BY account_count DESC;

Why it matters

More accurate users

Separating unique people from account records reduces the risk of overstating the size of the registered-user base.

Better funnel metrics

Duplicate registrations can affect registration-to-application conversion calculations if they are not handled consistently.

Verification context

Account count alone does not show whether a user successfully verified an email address.

Data quality monitoring

The same logic can be operationalised as a recurring data-quality check.

The summary values are portfolio-safe and do not expose individual email addresses or account records.
